# Text and translations

Every piece of text the user can see lives in a JSON file, never inside a component.

## How to show text

```tsx
import { t } from "@/i18n";

<h1>{t("seller.home.title")}</h1>
```

`t` works in server components and client components. If a key does not exist, the page shows the key itself (and the console warns in development), so mistakes are easy to spot.

## Where the text lives

| Text used by | File |
|---|---|
| Both apps | `packages/config/i18n/en/common.json` |
| Storefront only | `apps/storefront/src/i18n/messages/en.json` |
| Seller app only | `apps/seller/src/i18n/messages/en.json` |

Keys are dot-separated: `common.*`, `storefront.*` and `seller.*`.

The helper that reads these files is `packages/config/i18n/create-translator.ts`. It is shared by both apps.

## Adding a string

1. Add the key to the right JSON file.
2. Use it with `t("namespace.path")`.
3. Run `pnpm check:strings`.

## Text that also needs translating

- Page title and description: use `generateMetadata` in `layout.tsx` (see the existing layouts).
- Labels in `@waslu/ui` components (for example `closeLabel` on `Sheet`): pass them in with `t(...)`.

## The string check

`pnpm check:strings` reads `apps/*/src` and `packages/ui/src` and fails when it finds plain text in JSX, or in the attributes `placeholder`, `aria-label`, `title` and `alt`. It does not look at strings in other places such as `metadata`, so check those yourself.

To allow one exceptional line, put the comment `i18n-ignore-next-line` on the line above it.

## Adding a language

We only have English for now. When we add a second language, we will first extend `createTranslator` so a language can be chosen. Do not copy the JSON files for a new language before that issue exists.
